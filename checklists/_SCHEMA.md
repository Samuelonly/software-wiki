# checklists/ 字段格式定义

每个软件品类一份文件（如 `archive-utility.md`），文件内每条验收项一句人话。

## 先分清：两类清单，别混

| | stacks/ 的 `derived_checks` | checklists/ 的品类功能项 |
|---|---|---|
| 从哪来 | 技术选型派生（选了这套栈，必须避哪些雷） | 品类经验（做这类软件，用户会在哪骂娘） |
| 跟技术栈有关吗 | 强相关，换栈就换一套 | **零相关，换栈一条不少** |
| 判定 | 换掉技术栈后，这条还成立吗？成立 → 不进这里 | 换掉技术栈后，这条还成立吗？成立 → 进这里 |
| 例子 | "Tauri fs 权限 scope 要收窄" | "改了原文件但 backup 没保留" |

**判定口诀：换栈还在的，进 checklists/；换栈就没了的，进 stacks/ 的 derived_checks。**

## 条目格式

```markdown
## [品类名称]（如 压缩软件）

**来源**：[用户自己踩过的坑 / 某次 PRD 评审 / 竞品对比 / awesome-selfhosted#<category>]

### 验收项

- [ ] 改了原文件但没改 backup 时，backup 必须保留原内容
  - 来源：自己做过压缩软件被坑过
- [ ] 大文件（>100MB）解压后，磁盘临时空间要清理
  - 来源：竞品 Bandizip v7.0.3 泄漏临时文件
- [ ] 压缩包内 `../../etc/passwd` 这类路径要拦，不能写出目标目录
  - 来源：awesome-selfhosted#Archiving 中 9/12 个工具做过此校验

---
```

## 一条合格验收项的三条标准

1. **说"该有什么本事"，不说"怎么实现"**
   - ✅ 写"原文件不能被删"
   - ❌ 不写"用 copy-then-delete 模式"

2. **一句话能验完，不用看代码**
   - ✅ 外行照着念就能判
   - ❌ 不写"确保事务隔离级别是 SERIALIZABLE"

3. **用户真在乎，但买家想不到要问**
   - ✅ "改了 backup 没"
   - ❌ "能打开 zip 格式"（谁都能想到）

## 外行怎么看这个清单

用户不懂代码。他不验证实现，他只做一件事：**把清单逐条念给 AI，让它跑，然后看绿勾还是红叉。**

所以每条都必须满足：

- **描述是人话**——用户念得出来
- **判定有机器信号**——绿勾/红叉，不是"你觉得行不行"
- **红叉时用户能做决策**——驳回 / 接受 / 让 AI 再改一轮

出现"需要专家评估"的条目，说明它要么该拆成更小的机器判定，要么根本不该在这里。

## 来源写法

来源可以是：

| 写法 | 含义 |
|---|---|
| `自己踩过的坑：<简述>` | 第一手经验，最高价值 |
| `竞品对比：<产品名> <版本>` | 从竞品行为反推 |
| `awesome-selfhosted#<category>` | 从 awesome-selfhosted 对应品类下的软件反推 |
| `PRD 评审：<日期>` | 需求评审时挖出来的 |

`awesome-selfhosted` 的用法：它按品类列软件 + 打标签，可以当**竞品池**——拉出同品类 20 个产品，看它们的 README 和 issue，聚类出"这个品类用户在乎什么"，再改写成验收项。

**边界**：awesome-selfhosted 全是 self-hosted 服务端软件。做压缩 / 看图这类桌面工具，它在对应品类是空的，用不上；做聊天 / 网盘 / 笔记 / RSS 才用得上。

## 铁律

1. 条数因品类而异，**别凑数**。压缩软件可能 40 条，别的可能就 5 条。
2. 不确定的条目宁可不写；写了就得能验。
3. 每条标注来源——从哪次真实的坑里来的。
4. **换栈就不成立的条目，不收**——那属于 stacks/ 的 derived_checks。
5. 条目写人话，不说术语，不用看代码就能判。
6. **不许出现"需要专家判断"——出现就拆成更小的机器判定，或删掉。**

## 文件命名

`checklists/` 下每个软件品类一个文件，用小写 kebab-case：

| 文件 | 品类 |
|---|---|
| `archive-utility.md` | 压缩/解压软件 |
| `chat-app.md` | 即时通讯 App |
| `photo-editor.md` | 图片编辑器 |
| `password-manager.md` | 密码管理器 |

品类因实际项目驱动，**有人真要做才填，提前填的烂尾不算数**。
